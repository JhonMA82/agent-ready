# Example Notes — bad-generic

Read this when calibrating REJECT: advice that applies to any codebase is not a skill. Contrast with excellent-simple: same topic area, none of the execution.

## Why it fails (score sheet)
| Criterion | Score | Justification |
|---|---|---|
| necessity 25 | 15 | A nice-to-have; nothing requires this skill |
| repository_specificity 20 | 0 | Applies to any codebase; no repo, layout, or tooling |
| discovery_description 15 | 5 | Describes a topic, not a trigger |
| procedural_value 15 | 0 | Rules with no order, gates, or output contract |
| progressive_disclosure 10 | 5 | Minimal, but because nothing is disclosed |
| evidence_grounding 10 | 0 | No claim ties to a fact in this repository |
| validation 5 | 5 | Frontmatter pattern-valid as a sample |
| Total | 30 | REJECT |

## What to avoid
Topic-style descriptions, unanchored rules, no procedure, no output contract. REJECT is recorded in state with this justification.
